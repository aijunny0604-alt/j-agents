# 터치디자이너로 3D 플레이리스트 만들기

제작 과정 및 작업 규칙 · 2026-09-16

## 목표와 산출물

로고와 앨범 커버를 입체 장면으로 구성하고, 여러 곡을 실제 길이대로 재생하는 음악 영상과 편집 가능한 TouchDesigner 프로젝트를 만든다. 커버의 분위기와 로고의 글자 형태를 보존하면서 카메라 이동, 금속 반사, 물결과 주변 오브젝트로 깊이를 표현한다.

기본 납품 구성은 다음과 같다. 해상도·FPS·화면 비율은 작업별로 정한다.

- 편집 가능한 `.toe`와 필요한 상대 경로 자산
- 음악과 UI가 포함된 짧은 미리보기
- 전체 플레이리스트 MP4와 곡별 챕터
- 필요한 경우 별도의 무음 반복 커버 영상
- 한국어 실행 안내, 곡 목록, 검증 결과

## 1. 입력과 환경 조사

원본 이미지의 크기·투명도·로고 위치를 확인한다. 투명 로고가 있는지, 커버 안에 이미 같은 로고가 포함되어 있는지 살핀다. 곡 순서와 표기는 사용자의 요청을 우선하고 파일명 정렬만으로 결정하지 않는다.

음원 길이는 표시된 초 단위 숫자가 아니라 `샘플 수 / 샘플레이트`로 계산한다. 샘플레이트·채널 수·PCM 형식도 기록한다. 원본을 그대로 이어 붙이려면 형식이 같아야 하며, 다르면 명시적인 변환 단계를 둔다. 서로 다른 파일 형식을 단순 바이트 연결하지 않는다.

설치된 TouchDesigner 경로와 버전, 라이선스 상태, GPU, Python, FFmpeg를 확인한다. 지원 해상도와 코덱은 현재 설치 환경에서 확인하며 특정 버전의 제한을 보편적인 규칙으로 쓰지 않는다. 로그인·라이선스 활성화가 필요하면 사용자가 직접 처리하도록 요청하고 독립적인 자산 분석은 계속한다.

원본은 수정하지 않는다. 작업용 파일은 `work/`, 납품용은 `outputs/<project>/`에 둔다. 프로젝트는 사용자명이나 특정 드라이브에 고정하지 않고 `project.folder` 기준 상대 경로로 자산을 찾는다.

## 2. 커버를 입체 장면으로 분리

기본 구성은 배경 연기, 메인 로고, 주변 금속 파편, 물바닥, 광원, 화면 고정 UI다. 로고를 별도 오브젝트로 움직일 때 원래 커버의 로고가 뒤에 남아 이중으로 보이지 않게 한다.

필요하면 이미지 편집 도구로 중앙 로고만 제거한 배경을 만든다. 주변 파편·연기·물의 구도는 보존하고 수정 결과를 원본과 비교한다. 생성한 배경은 별도 자산으로 저장한다. 원본 로고를 임의로 다시 그려 글자 형태가 바뀌지 않게 한다.

## 3. 메인 로고의 실제 깊이

투명도 윤곽을 이용한 돌출 메시 또는 거리장(SDF) 솔리드를 사용한다. 두 방식 모두 전면, 베벨, 측면과 올바른 법선이 필요하다. 로고를 회전했을 때 옆면이 보여야 하며 화면 속 로고가 종이처럼 얇아지지 않아야 한다.

이번 사례에서는 2D 윤곽 거리장에 돌출 깊이·둥근 모서리·완만한 전면 곡률을 합쳐 광선 교차로 렌더링했다. 이는 실제 두께가 있는 SDF 형상이다. 원본 로고 내부의 모든 조각을 완전한 3D 모델로 복원한 것은 아니다. 앞면에는 원본의 반사 무늬가 남고 측면·추가 하이라이트는 동적으로 계산한다.

거리장과 법선 데이터를 일반 8비트 색상 이미지로 저장하면 음수 거리와 정밀도가 손실된다. 부동소수점 텍스처를 사용하고 채널 의미·좌표계·Y축 방향·월드 크기를 기록한다. 작은 윤곽 노이즈는 법선의 줄무늬로 확대되므로 형상 보존 범위에서 거리장과 법선을 매끄럽게 처리한다.

## 4. 원본 같은 크롬 재질

크롬은 밝은 회색 표면으로 끝내지 않는다. 검정과 은색의 강한 명암 차이, 날카롭지만 매끄럽게 이어지는 흰색 반사, 붉은 스트립 조명의 반사가 핵심이다. 카메라나 로고가 움직이면 반사 위치도 표면 법선을 따라 달라져야 한다.

PBR을 쓰면 금속도·거칠기·환경광을 함께 조절한다. 커스텀 셰이더를 쓰면 환경 반사, 길게 뻗은 흰색 광원, 붉은 림 반사와 베벨 하이라이트를 조합할 수 있다. 예술적으로 만든 환경 반사를 물리적으로 정확한 광선 추적이라고 설명하지 않는다.

확인할 기준:

- 측면이 무광 회색 덩어리로 보이지 않는다.
- 흰색 반사가 과노출되어 로고 윤곽을 지우지 않는다.
- 검정 부분에도 형태를 읽을 최소한의 반사가 있다.
- 회전 중 하이라이트가 갑자기 튀거나 줄무늬로 끊기지 않는다.
- 원본의 검정·은색·붉은색 관계와 글자 가독성이 유지된다.

## 5. 카메라와 오브젝트 모션

기본 위상은 `phi = 2*pi*t/T`다. 좌우 궤도 이동, 전진·후진, 높이 변화에 서로 다른 정수 배수의 사인·코사인을 사용하면 위치와 속도를 반복 경계에서 연결하기 쉽다. 로고에도 별도의 yaw·pitch를 넣어 카메라와 함께 움직이는 평면처럼 보이지 않게 한다.

액션감을 요청받으면 카메라 이동 폭과 로고 회전 폭을 높여 옆면과 원근 변화를 보여준다. 급격한 흔들림이나 임의의 컷을 추가하는 것으로 대체하지 않는다. 원근감이 가장 큰 프레임에서도 로고가 잘리지 않고 곡 제목과 재생 바가 읽히는지 확인한다.

주변 파편은 각기 다른 위상으로 천천히 회전·부유한다. 물은 낮은 진폭의 파동과 반사 왜곡으로 잔잔하게 흐르게 한다. 광원 변화도 공통 위상에 연결한다. 비주기적인 노이즈를 그대로 시간 이동시키면 첫 장면과 마지막 장면이 어긋날 수 있다.

전체 길이 `D`에서 배경이 정확히 반복되어야 하면 정수 반복 횟수 `N`을 정하고 `T=D/N`으로 둔다. 독립적인 30초 반복 영상은 별도의 `T=30`을 사용할 수 있다. 끝점 프레임을 중복 삽입하면 멈칫할 수 있으므로 `[0,T)`를 렌더링하고 `t=0`과 `t=T`는 별도 검증용으로 비교한다.

음악 반응, 곡 제목과 진행률은 자연스럽게 초기화될 수 있다. 배경의 반복이 매끄럽다는 사실만으로 음악 자체도 무봉제 반복이라고 말하지 않는다.

## 6. 실제 음원과 UI 동기화

곡별 시작 시각을 정확한 누적 길이로 관리한다. 현재 곡의 범위는 `[start,end)`로 정의한다. 곡 경계에서 다음 곡을 선택하고, 해당 곡의 경과 시간은 `t-start`, 진행률은 `clamp((t-start)/duration,0,1)`로 계산한다. UI 표시를 위해 초를 정수화하더라도 내부 시간은 반올림하지 않는다.

재생, 일시정지, 탐색과 오디오 출력은 같은 Position을 사용한다. 음원, 스펙트럼, 곡 제목, 진행 바에 서로 다른 독립 타이머를 두지 않는다. 오프라인 렌더링은 `t=frame/fps`를 사용한다.

실제 PCM 또는 Audio Spectrum CHOP으로 분석한다. 이번 사례의 출발값은 Hann 창 8192샘플, 초당 30회, 35~18000Hz의 로그 간격 64밴드였다. 샘플레이트에 따라 상한을 Nyquist 미만으로 조절한다. 빠른 attack·느린 release로 부드럽게 만들되 음악 반응이 지나치게 늦어지지 않게 한다. 무음·첫 샘플·마지막 분석 창의 범위도 처리한다.

전체 곡 목록과 현재 곡을 시각적으로 구분하고, 음악 감상을 방해하지 않는 위치에 경과 시간·총 길이·진행 바·스펙트럼을 배치한다. 제목이나 UI가 입체 로고를 가리지 않게 한다.

## 7. 미리보기 → 수정 → 전체 출력

먼저 짧은 구간으로 로고 두께, 크롬 반사, 가장 큰 카메라 움직임, 물과 파편, UI와 음악 반응을 확인한다. 사용자 수정사항은 기존 요청에 누적한다. 재질·모션이 바뀌는 동안 전체 길이 렌더링을 반복해서 시작하지 않는다.

짧은 프리뷰를 검토한 뒤 전체 렌더링한다. 사용자 피드백이 필요한 경우 구체적인 프레임이나 영상을 먼저 준비한다. 명시적인 승인이 필요한 작업이 아니라면 모든 단계에서 재확인을 요구하지 않는다.

TouchDesigner에서 직접 녹화하거나 동일 셰이더를 외부 GPU 렌더러에서 출력할 수 있다. 외부 출력은 그 사실을 납품 안내에 적는다. 편집 화면과 최종 출력의 해상도·글꼴·텍스처 샘플링·색상·프레임을 비교한다.

## 8. 완료 판정

- 저장한 `.toe`를 다시 열고 상대 경로 자산이 연결된다.
- GLSL Info DAT가 컴파일 성공을 표시하고 실제 렌더 프레임에 오류 패턴이 없다.
- 재생·일시정지·곡 경계를 넘는 탐색에서 오디오와 UI가 일치한다.
- 시작, 곡 전환 직전·직후, 마지막 곡과 마지막 프레임을 확인한다.
- `ffprobe`로 영상 해상도·FPS, 오디오 스트림·길이와 챕터를 확인한다.
- 한 프레임 이하의 영상 길이 반올림과 의도치 않은 오디오 절단을 구분한다.
- 반복은 끝점 비교와 실제 마지막→첫 프레임 재생 모두 확인한다.
- 테스트용 부트스트랩·절대 임시 경로·사용하지 않는 자동 실행 코드를 납품 프로젝트에서 제거한다.

## BURNWAY 제작 사례

7개의 48kHz 스테레오 PCM16 WAV와 투명 로고, 정사각형 커버를 사용했다. 음원 총 길이는 **1378.52초(22:58.52)**다.

| 순서 | 곡 | 길이(초) | 시작(초) |
|---|---|---:|---:|
| 1 | NO BRAKES | 175.56 | 0 |
| 2 | Burnway | 200 | 175.56 |
| 3 | BLACK FLAME | 237.16 | 375.56 |
| 4 | BURN AWAY | 221 | 612.72 |
| 5 | ONE WAY | 160.8 | 833.72 |
| 6 | NO SIGNAL | 156.44 | 994.52 |
| 7 | FLOAT AWAY | 227.56 | 1150.96 |

수정 과정은 평면 로고 적층 → 두께·베벨·곡률이 있는 SDF 로고 → 독립적인 로고 회전과 더 큰 카메라 이동 → 고대비 크롬 반사 및 법선 개선 순서였다. 가장 중요한 사용자 기준은 **메인 로고 자체의 입체감과 원본 같은 크롬**이었다.

최종 TouchDesigner 프로젝트는 재열기 후 셰이더 컴파일 성공과 오류 없음이 확인됐다. 편집 화면은 1280×720, 전체 MP4는 1920×1080·30fps였다. MP4는 동일 GLSL를 사용하는 ModernGL/FFmpeg 외부 GPU 렌더러로 출력했다. 검증된 영상 길이는 1378.533333초, 오디오는 1378.52초이고 7개 챕터가 들어 있다. 차이는 30fps 영상 프레임 단위 반올림 범위다.

이 수치와 설정은 이번 사례의 기록이며 다음 프로젝트의 고정 요구사항이 아니다. 저장소에는 원본 음원·이미지·대용량 영상 대신 문서와 재사용 도구만 보관한다.
