# /블로그검토 — 블로그 종합 최종 검수 에이전트 (v2.0)

> v2.0 (2026-11-18, 사장님 지시): 블로그 작성 시 **자동으로** 실행되는 종합 검수로 확장. 서사 검토(기존)에 **키워드 분석 · 업로드 사진 · 썸네일 · 패키지** 검수를 추가. `/팀퍼비드블로그`·`/무브모터스블로그` 8.9단계에서 이 파일을 Read해 3·3.5 체크리스트 전부를 그대로 수행한다.

## 실행 방식 (v2.1 — 2026-11-19)
- 작성 스킬 8.9단계에서는 **본문을 쓴 에이전트와 분리된 독립 에이전트(검수팀)** 로 파견해 실행한다. 검수 에이전트에는 작성자의 결론을 주지 말고 폴더 경로와 이 체크리스트만 준다.
- 사진이 많으면 업로드 사진 검수(B)와 키워드 검수(A)를 하위 에이전트로 나눠 병렬로 돌려도 된다.
- v2.2: 검수 단계는 `blog-fact-checker`(사실 검증)·`blog-compliance-checker`(법규·리스크 최종)를 먼저 병렬로 돌리고, 마지막에 `blog-reviewer`가 두 결과 반영 여부를 확인하며 A~D를 판정한다.

## 목적
사진 1장=1섹션으로 '개별 사진만 보고' 쓴 초안을, **완성본 전체를 하나의 작업기로 통독**하며 앞뒤 사진을 함께 분석해
**작업 진행 과정이 자연스럽고 타당한지(개연성)**, **섹션 간 연관·일관성**이 유지되는지 마지막으로 점검하고 **최소 교정**한다.
🚨 **지금의 글 스타일·톤·구조·분량은 그대로 유지한다.** 흐름·일관성·개연성에 걸린 부분만 손본다. 전면 재작성·스타일 변경·새 정보 창작 금지.

## 입력
- 인자: 블로그 폴더 경로 1개 (안에 `블로그_본문_v3.1.md` 와 `_upload\`(권장) 또는 원본 사진).
- 배치: 상위 폴더면 하위 각 폴더를 1건씩 검토. `[완료]`는 건너뛴다.

## 절차 (순서대로)
### 1. 초안 읽기
- `블로그_본문_v3.1.md` 를 Read. 제목·도입·각 사진 섹션·마무리·CTA·체크리스트 구조를 파악한다.

### 2. 사진을 '순서대로 통합' 재분석 (핵심)
- `_upload\` 의 사진을 **번호 순서대로 전부 Read**(없으면 원본을 첨부 순서로 Read).
- 🚨 이때 **한 장씩 따로 해석하지 말고**, 첫 장부터 끝 장까지 **하나의 연속된 작업 과정**으로 머릿속에 재구성한다.
  - "이 차가 어떤 상태로 들어와서(입고) → 무엇을 진단·탈거하고 → 어떤 신품이 들어가 → 어떻게 장착되어 → 어떤 완성으로 끝났는가"의 **한 줄기 흐름**을 먼저 잡는다.
  - 그 흐름 위에 각 섹션 설명이 올바른 위치에 있는지 본다.

### 3. 통합 점검 체크리스트 (각 항목 통과/수정)
1. **작업 진행 개연성·타당성**: 사진(섹션) 순서가 실제 작업 순서로 자연스럽게 이어지는가. 단계 **누락·역전·비약**이 없는가. (예: 탈거 없이 갑자기 장착 완료로 점프, 신품 소개가 장착 뒤에 나옴)
2. **앞뒤 사진 연관성**: 각 섹션이 **전/후 섹션과 인과로 연결**되는가. 앞에서 뗀 부품이 뒤에서 장착되는 식으로 맞물리는가. 개별 사진만 보고 써서 문맥이 끊기는 곳은 연결어·한 문장으로 자연스럽게 잇는다.
3. **용어·부품·차종 호칭 일관성**: 같은 부품을 앞뒤에서 **다른 이름**으로 부르지 않는가. 차종·코드(예: F30/G20)가 처음부터 끝까지 **일관**되는가.
3-1. 🚨 **단어 선택 SEO — 검색량 높은 단어 우선 (사용자 지시 2026-08, 필수 점검)**: 동의어·브랜드명 vs 일반명이 있을 때 **검색량 낮은 단어를 메인으로 쓴 곳이 없는지** 확인하고, 있으면 **검색량 높은 단어로 교체**한다(브랜드 정식명은 1회만 병기). 애매하면 `/네이버키워드`(naver_keywords.py)로 실검색량을 대조한다. 예: 본문이 `에어매틱`을 메인으로 썼는데 `에어서스펜션`이 검색 2,320 vs 20으로 116배 높음 → **에어서스펜션을 메인**으로 교체. `수온조절기 vs 써머스탯`, `라디에이터 vs 라지에이터`도 동일. 단 **제품 브랜드가 검색 유입에 강하면(JSR·아크라포빅·브릴란테 등) 유지**. 본문·해시태그·제목 모두 점검.
3-2. 🚨 **일상 단어·금지 표현 (사장님 지시 2026-11-18, 필수 점검)**: 본문·TXT·해시태그를 grep해 아래가 남아 있으면 자연스럽게 고친다.
   - `개구부` → 여유 공간·빈 공간·범퍼에 뚫린 자리·팁이 들어갈 자리
   - `둘레` → **직경** (원형 부품: 파이프·팁·플랜지). 예: "파이프 둘레를 따라 용접" → "파이프 직경 전체를 한 바퀴 돌려 용접"
   - 돌출량·체결부·인접 패널 등 딱딱한 한자어 → 튀어나온 정도·조이는 부분·옆 패널 (행거·데후·자바라 같은 현장 통용어는 유지)
   - AI·사진분석 표현(`사진상`, `보여집니다`, `확인할 수 있습니다`, `자료 기준`, `~듯`) 0건
4. **상태 모순**: 사진 실물 상태와 설명이 어긋나지 않는가(장착 완료 컷을 '장착 전'으로, 전면을 후면으로 등).
5. **중복·누락**: 같은 내용이 여러 섹션에 반복되는가. 흐름상 꼭 필요한데 빠진 연결 설명이 있는가.
6. **도입-본문-마무리 논리**: 도입에서 예고한 작업이 본문에서 실제로 다뤄지고 마무리·효과에서 정리되는가.
7. **사실 타당성**: 구동방식(FF/FR)·부품 구성상 물리적으로 말이 되는가(스킬의 기술 사실 규칙 준용).

### 3.5 종합 검수 — 키워드·사진·썸네일·패키지 (v2.0, 각 항목 통과/수정)
**A. 키워드 분석 검수**
- `검색량_분석.md`(또는 `kw_raw_*.json`)가 있는가. 없거나 조회 실패로 비어 있으면 `/네이버키워드`(naver_keywords.py)로 **재조회(최대 3회)** 후 작성한다.
- 제목 앞쪽에 **검색량 상위 키워드**가 들어갔는가(SEO 제목 공식). 차종명·작업명 중 검색량 높은 표기를 썼는가.
- 해시태그에 검색량 근거 있는 키워드가 포함됐는가. '10'은 10 미만 표시임을 메모에 반영했는가.
**B. 업로드 사진 검수** (`_upload\` 전부 Read)
- 본문 `[사진 N]` 수 = `_upload` 사진 수 = 첨부 순서표 행 수. 번호(`NN_라벨.jpg`)와 본문 참조 파일명 일치.
- 방향: 누워 있거나 뒤집힌 사진 0장(EXIF 회전 반영 확인).
- 로고: (팀퍼비드) 승인 로고 `assets/fervid_logo.png`가 좌상단에 전부 합성. (무브모터스) 로고 없음이 정상.
- 사진별 설명이 그 사진 실물과 맞는가(신품/구품·좌우·장착 전/후).
**C. 썸네일 검수** (팀퍼비드 — `00_썸네일_800x800.jpg` Read)
- 800×800, PSD 레이아웃(사진 영역·로고·차종명·작업명 2줄) 정상, 글자 잘림·넘침 없음.
- 사진 선택: 작업기 = 차량 전면 3/4(없으면 측면·후면 3/4·핵심 부품 순 대체) / **정보성 글 = 주제 부품의 제품 사진(전체가 보이는 컷)**.
- 🚨 **번호판이 보이면 불합격** → 모자이크 영역 재지정 후 재생성. 엠블럼은 가리지 않는다.
- 차종명·작업명 문구가 제목·본문과 일치.
**D. 패키지 검수**
- `블로그_본문_v3.1.md` · `블로그_네이버복사용.txt` · `블로그_미리보기.html` 내용이 서로 같은 최신본인가(교정 후 재생성했는가).
- 통합 ZIP에 `_upload` 사진·썸네일·TXT·MD·HTML·메모가 모두 들어 있고, 교정본이 반영됐는가.
- 금지 표현·타 상호(팀퍼비드 글의 무브모터스 정보 등) 자동 grep 0건.
- `편집_검수메모.md` 끝에 **A~D 결과표(항목/결과/조치)** 를 남긴다.

### 4. 최소 교정
- 문제된 부분만 **문장 교정 / 섹션 순서 조정 / 연결어·한두 문장 보강 / 호칭 통일**로 고친다.
- 🚨 **하지 말 것**: 전체 재작성, 톤·문체 변경, 섹션 분량 대폭 증감, 없는 사실 창작(불확실하면 오히려 단정 문구를 완화·삭제), 정형 리스트(작업요약/효과3) 삽입, 마크다운 `**` 볼드 추가.
- 섹션 순서를 바꾸면 **「사진 첨부 순서 체크리스트」 표와 `_upload\` 파일 번호도 함께 맞춘다.**
- 상호 규칙 준수: 팀퍼비드 글엔 무브모터스 단어 금지, 무브모터스 글엔 팀퍼비드·퍼비드모터스 단어 금지·CTA 자리표시자 유지.

### 5. 저장 + 보고
- 교정본을 같은 경로 `블로그_본문_v3.1.md` 에 덮어쓴다(Write/Edit).
- 본문을 고쳤으면 TXT·HTML·ZIP도 다시 만든다(D 항목). 썸네일·사진을 고쳤으면 ZIP도 갱신.
- 마무리에 **무엇을 왜 고쳤는지 1~3줄** + 종합 검수 한 줄 요약(예: "키워드 ✅ / 사진 12장 ✅ / 썸네일 번호판 가림 ✅ / 패키지 ✅") 보고. 고칠 게 없으면 "종합 검수 통과"를 명시.

## 금지 사항
- 스타일·톤·구조를 갈아엎지 말 것(사장님 지시: 지금 스타일 유지, 흐름만 최종 점검).
- 사진 근거 없는 정보 창작 금지. 불확실은 단정 완화/삭제.
- 팀퍼비드/무브모터스 상호·CTA 규칙 위반 금지.
