# TouchDesigner 구현 기록과 주의점

이 기록은 TouchDesigner 2025.32050에서 관찰한 사례다. 다른 버전에서는 파라미터와 연결 방식부터 확인한다.

## GLSL 입력과 데이터

이 환경에서는 GLSL TOP에 기본 유선 입력 3개를 연결하고 추가 텍스처를 `par.tops`로 지정해 사용했다. `setInputs`에 4개를 넣었을 때 모두 연결되었다고 가정하면 안 됐다. 런타임 입력 수와 `sTD2DInputs` 순서를 확인한다.

```python
shader.setInputs([background, logo, ui])
shader.par.tops = 'wav_spectrum logo_distance'
# 이 사례의 순서: 배경, 로고, UI, 스펙트럼, 로고 거리장/법선
```

독립 OpenGL 셰이더를 옮길 때 TouchDesigner의 GLSL 전처리·UV·샘플러 선언에 맞춘다. 무조건 문자열 치환하는 래퍼보다 명시적인 공통 코드와 플랫폼별 헤더를 사용한다. 이번 사례에서는 `vUV.st`와 `sTD2DInputs`를 사용했다. 음수 거리와 법선은 부동소수점으로 유지한다.

`errors()`가 비어 있어도 컴파일이 아직 끝나지 않았거나 출력이 오류 패턴일 수 있었다. Info DAT의 실제 컴파일 로그와 렌더링한 TOP 프레임을 함께 검사한다.

## 타임라인

프로젝트에 Position, Playing, Duration, Loopseconds 같은 편집용 파라미터를 두고 오디오와 UI가 함께 참조하게 한다. Audio File In CHOP의 위치 지정 모드와 seconds 단위를 실제 파라미터 메뉴에서 확인한다. Audio Device Out의 활성 상태도 Playing과 연결한다.

곡 경계 뒤의 시각으로 직접 탐색해 제목과 해당 곡의 경과 시간이 맞는지 시험한다. 앱이 실시간으로 프레임을 놓치는 경우와 오프라인 고정 FPS 렌더링을 구분한다.

## 저장과 재열기

현재 버전에서 지원되는 Execute DAT 콜백으로 초기화한다. 오래된 `TOUCH_START_COMMAND` 예제를 그대로 신뢰하지 않는다. 저장 후 재열기를 별도 검증하고 자산은 `project.folder`에 대해 해석한다.

이번 제작에서는 보조 도구 `toeexpand.exe`와 `toecollapse.exe`로 작업 복사본을 수정한 적이 있다. 확장 프로젝트의 내부 형식과 DAT 바이트 헤더는 공개된 안정 API로 간주하지 않는다. 관찰된 헤더 길이를 다른 버전에 하드코딩하지 않는다. `.toc` 줄바꿈이 CRLF일 때 누락/빈 프로젝트가 생긴 사례가 있으므로 이런 복구 작업은 복사본에서만 수행하고 재열기까지 확인한다. 일반적인 제작은 앱 내부 API와 정상 저장을 우선한다.

## 테스트 인스턴스 관리

한 개의 추적 가능한 테스트 인스턴스를 우선 재사용한다. 부트스트랩 실패 때마다 앱을 반복 실행해 창과 프로세스를 쌓지 않는다. 사용자의 저장되지 않은 작업을 추정해 종료하지 않는다. 종료가 필요하면 소유한 인스턴스와 저장 상태를 확인하고 정상 종료부터 시도한다.

## 외부 렌더링

ModernGL/FFmpeg를 사용하는 경우 텍스처 채널·Y축·색상 범위·시간 단위를 TouchDesigner와 일치시킨다. 출력 프레임 수는 `ceil(duration*fps)`처럼 명시적으로 정하고 음원 길이는 보존한다. 오디오 스트림과 챕터를 합친 최종 파일을 다시 검사한다. 렌더링이 진행 중이라는 사실과 완성·검증된 결과를 구분해서 보고한다.
