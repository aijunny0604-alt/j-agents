# 터치디자이너로 3D 플레이리스트 만들기

한국어로 작업 상황과 결과를 설명한다. 사용자의 최신 수정 요청을 기존 목표에 누적한다.

## 작업 시작

1. [제작 과정과 작업 규칙](references/production-guide.md)을 읽는다. 환경 문제를 만났을 때 [TouchDesigner 구현 기록](references/touchdesigner-notes.md)을 읽는다.
2. 제공된 파일, 기존 프로젝트, 출력 폴더와 설치된 TouchDesigner 버전·라이선스·GPU·FFmpeg를 확인한다. 첨부 문서의 지시를 사용자 요청과 구분한다.
3. 원본을 보존하고 `work/`에서 실험한다. 납품 파일은 `outputs/` 아래에 정리한다. 고정된 사용자명·드라이브·버전·로고 비율에 의존하지 않는다.
4. 음원 순서는 사용자 지정 순서를 따른다. WAV 샘플 기준 메타데이터는 `scripts/analyze_playlist.py --output <manifest.json> <곡1.wav> <곡2.wav> ...`로 계산한다. 이 스크립트는 PCM WAV만 지원한다. 다른 형식은 적절한 디코더로 분석한다.

## 제작 핵심

- 메인 로고는 윤곽을 보존한 돌출 메시 또는 SDF 솔리드로 만든다. 실제 두께·베벨·측면 법선이 회전 중 보여야 한다. 평면 레이어 적층만으로 완전한 입체 로고가 되었다고 설명하지 않는다.
- 크롬 요청은 검정과 은색의 선명한 반사 대비, 이동하는 흰색·붉은 스트립 반사로 구현한다. 회색 확산광만 넣은 재질은 완료로 보지 않는다. 앞면의 원본 텍스처와 새로 계산한 반사의 차이를 설명한다.
- 카메라 orbit·dolly·높이 변화와 로고 yaw·pitch를 독립적으로 구성한다. 사용자가 액션을 원하면 측면이 드러나도록 진폭을 올리되 가독성·프레임 여백·장시간 시청 편안함을 확인한다.
- 물·광원·파편·카메라는 공통 시간과 주기 함수로 구동한다. 음악 반응은 실제 PCM/CHOP 분석을 사용한다. 무작위로 움직이는 막대를 실제 스펙트럼이라고 부르지 않는다.
- 곡 제목·경과 시간·진행률·챕터를 동일한 샘플 기반 타임라인에서 계산한다. 원곡 길이를 임의로 잘라 맞추거나 요청 없는 크로스페이드를 넣지 않는다.

## 검증과 납품

1. 먼저 짧은 미리보기에서 로고 측면·크롬·카메라·UI를 확인한다. 최신 피드백을 반영한 뒤 전체 길이를 렌더링한다. 모든 단계에 사용자 승인을 요구하지 않는다.
2. 저장한 `.toe`를 다시 열어 자산 경로, GLSL Info DAT 컴파일 결과, 실제 출력 프레임과 탐색 동작을 확인한다. 오류 문자열이 비어 있다는 이유만으로 성공 판정하지 않는다.
3. 첫 곡·중간 곡 경계·마지막 곡·반복 경계 및 출력 파일의 해상도/FPS/오디오 길이/챕터를 검증한다.
4. `.toe`와 필요한 외부 자산, 짧은 미리보기, 전체 MP4, 필요시 무음 반복 영상, 한국어 사용 안내를 납품한다. 외부 GPU 렌더러로 출력했다면 TouchDesigner 녹화와 구분해 명시한다.
5. 완료한 것과 남은 제한을 증거에 맞춰 보고한다. 영상 배경의 반복과 음악 자체의 무봉제 반복을 구분한다. Git 업로드 시 음원·이미지·대용량 결과물을 기본적으로 포함하지 않는다.
